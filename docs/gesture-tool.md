# 워치 제스처 툴 사용법 (#41)

갤럭시 워치에서 제스처를 하면 **어떤 제스처인지 화면에 보여주고 진동**으로 알려주는 툴이다.
AI 모델 학습용 **데이터 녹화** 기능도 들어 있다.

- 코드: `android/gesture` (인식 로직), `android/wear` (워치 앱)
- 설계: `docs/uml/gesture-recognizer.puml`, `docs/uml/wear-gesture-tool.puml`

## 1. 빌드

```powershell
cd android
.\gradlew :gesture:test          # 인식 로직 단위 테스트 (워치 없이 PC에서)
.\gradlew :wear:assembleDebug    # 워치 앱 APK → wear/build/outputs/apk/debug/wear-debug.apk
```

- Android Studio에서는 `android/` 폴더를 열면 된다.
- 명령줄로 빌드하려면 `android/local.properties`에 SDK 위치가 필요하다. 이 파일은 커밋하지 않는다.
  예) `sdk.dir=C\:/Android/Sdk`
- ⚠️ Claude 데스크톱 앱(Microsoft Store 버전)이 SDK를 설치하면 `AppData\Local` 아래 경로가
  앱 전용 폴더(`AppData\Local\Packages\Claude_...\LocalCache\...`)로 숨겨져 다른 터미널에서 보이지 않는다.
  SDK는 `C:\Android\Sdk`처럼 `AppData` 밖에 둔다.

## 2. 갤럭시 워치에 설치 (무선 디버깅)

1. 워치 **설정 → 워치 정보 → 소프트웨어 정보 → 소프트웨어 버전**을 5번 누르면 개발자 옵션이 켜진다.
2. **설정 → 개발자 옵션**에서 **ADB 디버깅**과 **무선 디버깅**을 켠다. PC와 워치는 같은 Wi-Fi에 있어야 한다.
3. 무선 디버깅 → **새 기기 페어링**을 누르면 IP:포트와 페어링 코드가 나온다.

```powershell
adb pair 192.168.0.23:41234      # 페어링 화면의 IP:포트, 코드 입력
adb connect 192.168.0.23:5555    # 무선 디버깅 화면의 IP:포트
cd android; .\gradlew :wear:installDebug
```

`adb`는 SDK 폴더의 `platform-tools\adb.exe`에 있다. (예: `C:\Android\Sdk\platform-tools\adb.exe`)

## 3. 사용법

| 메뉴 | 하는 일 |
|---|---|
| **실시간 인식** | 제스처를 하면 이름, 확신(%), 판단 근거 숫자를 보여주고 진동한다. 확신이 낮으면 "모르겠어요"라고 답한다. |
| **데이터 모으기** | 라벨을 고르고 **녹화**를 누른다. 짧은 진동 3번(3초 카운트다운) 후 긴 진동이 오면 2.5초 동안 동작을 한다. |
| **착용: 왼손/오른손** | 워치를 찬 손을 고른다. 오른손은 워치 방향 설정을 바꾸지 않은 기본 상태를 뜻한다. |

### 제스처 목록

모든 제스처는 **"빠르게 갔다가 돌아오기" 한 번**이다. 돌아오는 동작까지 한 번에 해야 반대 제스처로 잘못 인식되지 않는다.
삼성 유니버설 제스처(주먹 쥐기, 손가락 맞대기, 손목 두 번 흔들기)와 겹치지 않게 팔과 손목 전체를 쓰는 동작만 골랐다.

| 제스처 | 동작 | 로봇카 동작 (안, #34에서 확정) |
|---|---|---|
| ↻ 손목 시계방향 | 팔꿈치에서 손 쪽을 볼 때 시계방향으로 손목을 돌렸다 돌아오기 | 제자리 우회전 |
| ↺ 손목 반시계방향 | 반대로 돌렸다 돌아오기 | 제자리 좌회전 |
| ⬆ 앞으로 뻗기 | 팔을 손가락 방향으로 툭 뻗었다 돌아오기 | 전진 |
| ⬇ 당기기 | 팔을 몸 쪽으로 툭 당겼다 돌아오기 | 이리 와 (다가오기) |
| ⬅ 왼쪽 휘두르기 | 손등을 위로 하고 팔을 왼쪽으로 휘둘렀다 돌아오기 | 왼쪽으로 옆 이동 |
| ➡ 오른쪽 휘두르기 | 오른쪽으로 휘둘렀다 돌아오기 | 오른쪽으로 옆 이동 |
| ✋ 아래로 누르기 | 손등을 위로 하고 손을 아래로 툭 눌렀다 돌아오기 | 정지 |
| · 일상 동작 | 걷기, 컵 들기, 머리 만지기 등 (녹화용 라벨) | 아무것도 안 함 |

## 4. 인식 방식 (지금: 규칙 기반)

1. **동작 구간 자르기** (`MotionSegmenter`)
   - 가속도에서 중력을 뺀다. 중력은 0.3초 저역통과 필터로 추정한다.
   - 자이로 1.5 rad/s 또는 가속도 3 m/s²를 넘으면 구간을 시작한다.
   - 0.2초 동안 조용하면 구간을 끝낸다.
   - 길이가 0.15~2초인 구간만 제스처 후보로 본다. 걷기처럼 계속되는 움직임은 버린다.
   - 끝난 뒤 0.5초 동안은 새 동작을 받지 않는다. 팔이 제자리로 돌아오는 반동을 무시하기 위해서다.
2. **판단** (`RuleBasedGestureRecognizer`)
   - 손목 비틀기(X축 회전)의 **첫 봉우리 회전량**이 0.8 rad(약 46도)를 넘으면 손목 회전으로 본다. 부호로 시계방향과 반시계방향을 가른다.
   - 아니면 가속도가 가장 큰 축과, 그 축에서 **처음 움직인 방향**으로 판단한다.
   - 한 축이 다른 축보다 뚜렷할수록 확신이 높다. 50% 미만이면 일상 동작으로 답한다.
3. 기준값은 `SegmenterConfig`, `RuleConfig`에 모여 있다. 실제 워치에서 화면 아래 숫자(회전량, 축별 가속도, 길이)를 보면서 조정한다.

> 규칙 기반은 출발점이다. 데이터가 모이면 같은 `GestureRecognizer` 인터페이스로 TFLite 모델 인식기를 만들어 갈아끼운다(#44). 워치 앱 코드는 바꾸지 않아도 된다.

## 5. 녹화 데이터 가져오기

```powershell
adb pull /sdcard/Android/data/com.watchout.wear/files/gestures data/gestures
```

`data/`는 `.gitignore`에 있어서 커밋되지 않는다. 팀 공유 드라이브에 올린다.

### 데이터 형식 (제안: 팀 합의 후 CLAUDE.md "데이터 규칙"에 기록)

- 파일 이름: `<라벨>__<yyyyMMdd-HHmmss-SSS>.csv` (예: `push__20261127-101530-120.csv`)
- 녹화 하나 = 파일 하나, 2.5초, 약 50Hz (약 125줄)

```
# label=push,hand=LEFT,rate_hz=50,started_at=2026-11-27T10:15:30.120+09:00
timestamp_ms,ax,ay,az,gx,gy,gz
0,0.01234,0.10000,9.81000,0.00100,0.00000,0.00200
```

| 컬럼 | 단위 | 설명 |
|---|---|---|
| timestamp_ms | ms | 녹화 시작을 0으로 한 시간 |
| ax, ay, az | m/s² | 가속도 (중력 포함, 원본) |
| gx, gy, gz | rad/s | 자이로 (원본) |

- 축: X = 3시 방향(용두 쪽), Y = 12시 방향, Z = 화면에서 나오는 방향
- 값은 착용 손 보정 **전** 원본이다. 학습 코드에서 `hand=RIGHT`이면 ax, ay, gx, gy의 부호를 뒤집는다.
- pandas로 읽기: `pd.read_csv(path, comment="#")`
